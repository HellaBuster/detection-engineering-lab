# Detection Engineering Lab

A long-term, mastery-gated engineering program focused on:

- browser systems
- Playwright and browser automation
- web and networking fundamentals
- telemetry and event data
- SQL and data analysis
- statistics
- machine learning
- fraud and abuse detection
- production detection systems

This repository is both a learning environment and a public proof-of-work portfolio.

## Learning model

The program is AI-guided, but progression is evidence-based.

A topic is not considered complete because it was explained, attempted, or felt familiar. It is complete only when the learner demonstrates understanding through explanation, prediction, experiment, transfer, and evaluation.

The learner uses:

- a physical notebook for thinking, diagrams, formulas, hypotheses, and conclusions;
- this repository for persistent context, labs, evidence, projects, and progress;
- an AI agent as teacher, evaluator, lab designer, reviewer, and curriculum controller.

## Core principle

**The AI agent controls progression.**

The learner cannot self-approve a topic or skip a required prerequisite just by asking. If mastery is incomplete, the agent must block progression and provide focused remediation.

## Real-world first

Labs should prefer, in order:

1. real public datasets;
2. real permitted websites or public APIs;
3. real logs produced by the learner's own systems;
4. open-source applications in controlled environments;
5. synthetic data only when the above are unsuitable.

Synthetic data must always be labeled and justified.

## Repository map

- `AGENTS.md` — operating contract for the AI agent
- `curriculum/` — learning rules, roadmap, assessment, mastery policy
- `progress/` — current state and authoritative mastery record
- `labs/` — focused experiments and demonstrations
- `projects/` — larger engineering systems
- `case-studies/` — investigation and decision writeups
- `datasets/` — permitted real-world and synthetic datasets
- `assets/` — diagrams, screenshots, selected notebook pages

## Start a session

The AI agent must read:

1. `AGENTS.md`
2. `curriculum/MASTERY_GATE_POLICY.md`
3. `curriculum/ROADMAP.md`
4. `progress/CURRENT.md`
5. `progress/MASTERY.md`
6. `progress/PROGRESS.md`
7. `progress/OPEN_QUESTIONS.md`
8. `progress/DECISIONS.md`

Then continue from the current state.

The learner should be able to say only:

> Continue training.

and the agent should know what to do.

## Long-term outcome

The repository should gradually become evidence that the learner can:

- understand unfamiliar technical systems;
- reason about browser and network behavior;
- inspect and debug code generated with AI assistance;
- work with event data and SQL;
- evaluate ML models for imbalanced problems;
- reason about false positives, thresholds, drift, and abuse signals;
- design and test detection systems;
- communicate technical findings clearly.

The goal is not to become a fast typist of code. The goal is to become an engineer who understands systems and can direct tools, including AI, with judgment.
