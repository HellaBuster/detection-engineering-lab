# Career Evidence Strategy

The repository is public proof of work, not a certificate dump.

## Strong evidence

- labs with prediction and result;
- case studies;
- debugging writeups;
- real-world datasets;
- SQL analysis;
- model evaluation;
- architecture decisions;
- false-positive investigations;
- production-style monitoring;
- documented trade-offs.

## Weak evidence

- copied tutorials;
- giant generated codebases without explanation;
- "completed course" badges;
- long lists of technologies with no artifacts;
- trivial CRUD apps unrelated to the target field.

## AI transparency

Do not hide AI assistance.

Present it accurately:

> AI-guided, mastery-gated self-directed engineering curriculum.

The value comes from:

- independent mastery checks;
- labs;
- reasoning;
- projects;
- case studies;
- Git history.

## Final portfolio narrative

The repository should eventually demonstrate:

1. browser and web understanding;
2. data and SQL competence;
3. ML evaluation competence;
4. detection reasoning;
5. ability to investigate real system behavior;
6. ability to use AI without outsourcing judgment.
